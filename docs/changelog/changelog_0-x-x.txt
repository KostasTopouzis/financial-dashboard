# The Ashby & Vale financial dashboard changelog

v0.1.0: Initial version after completing the Next.js App Router tutorial | 2026-11-22 17:36

Category: architecture

- Next.js App Router project (React 19, TypeScript, Tailwind CSS)
  with a Postgres database reached through the postgres client over
  SSL, using the POSTGRES_URL environment variable.
- app/layout.tsx: root layout with the Inter font, global styles and
  shared metadata (title template "%s | Acme Dashboard",
  description, metadataBase). Each page sets its own title.
- app/dashboard/layout.tsx: shared dashboard shell with the SideNav
  (navigation links and a sign-out button) and the page content.
- app/lib/data.ts: server-side read queries for revenue, latest
  invoices, card totals, filtered and paginated invoices (6 per
  page), a single invoice and customers. Card totals run three
  queries in parallel with Promise.all.
- app/lib/actions.ts: Server Actions for creating, updating and
  deleting invoices. Form data is validated with Zod, amounts are
  stored in cents, field errors are returned to the form, and the
  invoices page is revalidated and redirected to on success. Also
  holds authenticate(), which signs users in with credentials.
- app/lib/definitions.ts and app/lib/utils.ts: shared types and
  helpers (currency and date formatting, revenue chart y-axis
  labels, pagination numbers).
- app/dashboard/(overview)/page.tsx: dashboard overview that streams
  the KPI cards, revenue chart and latest invoices separately inside
  Suspense boundaries, with skeletons and a route-level loading.tsx.
- app/dashboard/invoices/page.tsx: invoice list driven by the query
  and page URL search parameters. The search input updates the URL
  with a 300 ms debounce, and the table is wrapped in Suspense with
  a skeleton fallback.
- app/dashboard/invoices/create and [id]/edit: invoice forms built on
  useActionState, with per-field error messages linked through
  aria-describedby. The edit page loads the invoice and customers in
  parallel and calls notFound() for unknown ids.
- app/dashboard/invoices/error.tsx and [id]/edit/not-found.tsx:
  error boundary with a retry button and a 404 page for invoices.
- auth.config.ts, auth.ts and proxy.ts: NextAuth.js v5 with a
  Credentials provider. Credentials are validated with Zod, users are
  looked up in the users table and passwords are compared with
  bcrypt. The proxy protects /dashboard and sends signed-in users
  away from /login.
- app/login/page.tsx and app/ui/login-form.tsx: login page with a
  pending state and an error message for invalid credentials.
- app/seed/route.ts: GET /seed creates the users, customers,
  invoices and revenue tables and fills them with placeholder data
  in a single transaction, hashing user passwords with bcrypt.
- app/query/route.ts: GET /query, a test endpoint from the tutorial
  that returns the invoices with an amount of 666.
- app/dashboard/customers/page.tsx: placeholder Customers page. The
  fetchFilteredCustomers() query exists but is not used yet.

Category: frontend

- Generic design and brand identity provided by the tutorial itself.

v0.3.0: Dark mode with a Light / Dark / System switcher | 2026-11-23 14:39

Category: frontend

- app/lib/theme.ts: new theme module. The preference (light, dark or
  system) is stored in localStorage, and the resolved theme is set on
  <html data-theme>. An inline script applies it before the first
  paint (no flash of the wrong theme), follows OS changes while the
  preference is "system" and syncs other tabs. Falls back to an
  in-memory preference when storage is blocked.

  control built on visually hidden native radios, read through
  useSyncExternalStore to avoid hydration mismatches.
- app/ui/dashboard/sidenav.tsx: theme switcher added above the
  sign-out button.
- app/layout.tsx: inlines the theme script in <head>, suppresses the
  expected hydration warning on <html> and sets color-scheme and

v0.4.0: Personal workspace for each user | 2026-11-25 13:13

Category: architecture

- app/lib/dal.ts: new Data Access Layer. requireUser() reads the
  session once per request (React cache) and returns the signed-in
  user's id, name and email, or redirects to /login.
- app/lib/data.ts: every query calls requireUser() and filters by
  user_id. Search conditions are grouped in parentheses so the user
  filter always applies. Revenue is sorted by calendar month. The
  connection() calls are removed, as reading the session already
  renders these pages per request.
- app/lib/actions.ts: create, update and delete invoice actions check
  the caller with requireUser(). New invoices store the owner's id;
  updates and deletes only match the owner's rows, and an update that
  matches nothing returns "Invoice not found".
- auth.config.ts: the session callback copies the user id from the
  token into session.user.id. Signed-in users are only redirected to
  the dashboard from / and /login, so routes like /seed still run.
- auth.ts: authorize() returns only id, name and email, never the
  password hash.
- app/seed/route.ts: customers, invoices and revenue get a user_id
  column. A composite foreign key (customer_id, user_id) stops an
  invoice from pointing at another user's client. Revenue is keyed by
  (user_id, month). Existing databases are upgraded in place: old
  rows are given to the original demo user. New indexes on the
  owner columns. All steps run in order inside one transaction, and
  invoices are only seeded into an empty workspace, so the route can
  be run again safely.
- app/lib/placeholder-data.ts: every customer, invoice and revenue row
  has an owner. Adds a second demo user (user2@nextmail.com) with
  three clients, four invoices and its own revenue figures.
- app/query/route.ts: removed the tutorial test endpoint.

Category: frontend

- app/ui/dashboard/sidenav.tsx: shows the workspace owner's name and
  email above the navigation (hidden on mobile).

Category: documentation

- docs/progress.md: user workspaces done; the sign-up page is next.
- README.md: version (0.4.0), New Features and the second demo
  account in How to Run.
- package.json: version bumped to 0.4.0.
